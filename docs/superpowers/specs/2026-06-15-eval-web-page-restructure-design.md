# runtime_eval 前端页面拆分重构 设计文档

- 日期：2026-06-15
- 范围：`runtime_eval/runtime_eval/eval_web`（静态 SPA，纯非模块化 JS，无构建）
- 目标：消灭"向导 vs 单页"两套并行入口造成的重复与混乱，改为**以项目为中心**的信息架构。

## 1. 背景与问题

eval-web 是一个三服务架构里的前端：eval-web（静态 SPA）→ eval-api(:8800) → eval-llm(:8801)。

当前顶部导航有 6 个入口：看板总览、评估流程（四步向导）、测试集管理、黄金标注、评估报告、对话试问（外加一个隐藏的"检索评估"页）。

核心问题是**重复与并行**：

- 「评估流程」四步向导的第 ①②步（上传文档 + 出题）与「测试集管理」整页重叠；
- 向导第 ②步（黄金集）与「黄金标注」整页重叠；
- 向导第 ④步（报告）与「评估报告」整页重叠；
- 「检索评估」页是死链，点进去直接 `go("flow")` 跳回向导。

结果：同一件事有两条路可走，用户不知道点哪个；导航看着 6 项，实际只在干 4 件事（传文档+出题 / 校对黄金 / 跑评测看证据 / 看报告）。

## 2. 设计目标

1. 导航只反映"真正不同的几件事"，不再有重复入口。
2. 把分散的页面收进"项目"这个统一上下文里，让页面之间不再是孤岛。
3. 每个功能区的可用空间不缩水——每一步都是独立整页，功能多的步骤还能在内部再分子标签。
4. 尽量复用现有 renderer，做"搬家"而非"重写"，控制改动风险。

## 3. 新信息架构（IA）

### 3.1 顶层导航（6 → 3）

```
看板总览  |  项目  |  对话试问
```

- **看板总览**：概览/快捷入口，基本沿用现有 `renderDashboard`，加一个"新建项目"CTA。
- **项目**：核心。先是项目列表，点进去是某个项目的工作台（见 3.3）。
- **对话试问**：独立工具，沿用现有 `renderChat`，不动。

删除：评估流程向导外壳、测试集管理、黄金标注、评估报告这 4 个独立导航项，以及隐藏的"检索评估"页与其重定向。

### 3.2 项目列表

- "+ 新建项目"按钮（沿用现有建项目逻辑）。
- 项目卡片/行，每条显示：项目名、文档数、题数、上次评测综合分、状态（未评测/已评测）。
- 点一条 → 进入该项目工作台。

### 3.3 项目工作台

"工作台"= "选中某个项目"这一上下文，**不是把多块功能挤进一个小页面**。结构：

1. **项目上下文条（钉在顶部）**：显示当前项目名（可下拉切换 / 返回列表）+ 关键摘要（题数、上次分数）。
2. **步骤条（二级导航）**：`① 文档与出题  →  ② 黄金校对  →  ③ 评测与报告`。
   - 带进度/解锁提示：复用现有向导的 `/api/v1/suites/{sid}/state` 解锁逻辑（`flowUnlocked`/`flowDone`），但改成**软提示**——某步未就绪时给灰显+提示文案，仍允许点回任意步（比现在的硬向导灵活）。
3. **整页内容区**：占满屏幕宽度，等于把现有单页原样搬进来。功能多的步骤在内部再开子标签/分区。

各步内容来源：

| 步骤 | 内容 | 复用的现有 renderer |
|------|------|--------------------|
| ① 文档与出题 | 上传文档、出题/导入、批量拉取、查看提示词 | `renderSuites`（663）+ flow 的 `flowStepDocuments`/`查看提示词` 预览逻辑 |
| ② 黄金校对 | 黄金集库可编辑、确认状态 | `renderGold`（845）|
| ③ 评测与报告 | 子标签：[跑评测]（agent 逐题/serving 取证 SSE）[证据包][报告历史] | `renderFlow` 第③④步（`flowStepEvidence`/`flowStepReport`）+ `renderReports`（344）|

## 4. 路由

现有为 hash 路由（`go(page)` → `location.hash`，`PAGES` + renderers map + 中央点击代理）。调整为：

- `#dashboard` — 看板
- `#projects` — 项目列表
- `#project/<pid>?step=docs|gold|eval` — 某项目工作台 + 当前步骤（默认步骤按 `/state` 决定，沿用 `flowDefaultStep`）
- `#chat` — 对话试问

需要把现有的 `PAGES` map、renderer 分发、点击代理改造为支持带参数的项目路由（解析出 `pid` 和 `step`）。

## 5. 复用与改动清单

**直接复用（搬家）**：
- `renderSuites` → 步骤①内容
- `renderGold` → 步骤②内容
- `renderFlow` 第③④步 + `renderReports` → 步骤③（内部分子标签）
- flow 的 `/state` 解锁逻辑 → 步骤条进度/提示
- `renderDashboard` / `renderChat` 基本不动

**新写**：
- 项目列表页（卡片 + 新建项目）
- 工作台外壳（项目上下文条 + 步骤条组件 + 内容容器）
- 步骤③内部子标签切换

**删除/改造**：
- `renderFlow` 外壳（四步向导独立页）
- "检索评估"页与 `go("flow")` 重定向
- 旧导航项（suites/gold/reports/flow）从 `index.html` nav 与 `PAGES` 移除
- 路由解析加 `#project/<pid>?step=` 支持

**后端**：本次重构以纯前端 IA 调整为主，不改 eval-api / eval-llm 端点；沿用现有 `/state`、suites、gold、reports、generate/preview、run-agent、serving 取证等接口。

## 6. 错误与边界处理

- 进入 `#project/<pid>` 时 `pid` 不存在 → 回退到项目列表并提示。
- 步骤未就绪（如无题就切到②）→ 软提示+灰显，不报错、不硬跳。
- 步骤③子标签：无报告历史时显示空态，不留死区。
- 切换项目下拉 → 清空当前步骤态，按目标项目 `/state` 重新定位默认步骤。

## 7. 测试策略

- 前端无构建、无既有前端单测框架，主要靠 eval-api 现有 pytest 回归保证后端接口未受影响（重构不动后端，应保持 76 项全绿）。
- 手动验收清单：
  1. 导航只剩 3 项；旧入口与死链均无。
  2. 新建项目 → 列表出现 → 点进工作台。
  3. ①②③ 三步内容与旧页一致，空间不缩水。
  4. 步骤条软提示正确（未就绪灰显但可点）。
  5. 步骤③子标签可切换，报告历史正常。
  6. 刷新后按 hash 恢复到正确项目+步骤。

## 8. 非目标（YAGNI）

- 不做视觉风格大改（沿用现有 `styles.css`）。
- 不引入前端构建工具/框架。
- 不改后端数据模型与接口。
- 不做多项目并排对比等新功能。
