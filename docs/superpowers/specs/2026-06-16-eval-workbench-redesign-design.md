# 评估工作台改造设计（概念重构 + UI 重做）

- 日期：2026-06-16
- 范围：`runtime_eval` 的 eval-web 前端 + eval-api 后端
- 背景：当前工作台名词混乱（测试集/用例集/题库三个叫法）、黄金库与测试集职责重叠让用户反复困惑、步骤区渲染成一坨文字、不支持删除项目、导入测试集无法命名。本设计统一概念、退役黄金库、重做步骤流，并补齐删除/命名/编辑能力。

---

## 1. 核心概念统一

**模型（一句话）：项目 = 题库 = 一个大池子；往池子里分批导入「测试集」；每个测试集自带「问题 + 标准答案」，答案即评分基准。**

| 旧叫法（混乱） | 新统一叫法 | 含义 |
|---|---|---|
| 题库 / 用例集 / 测试集 | **项目**（顶层池子）/ **测试集**（项目下批次） | 项目是题库大池子，测试集是倒进去的一批题 |
| 黄金集库 / 已确认黄金 | 取消（退役藏起来） | 答案直接存在测试集里，不再单列「黄金」 |
| 导入题库 | **导入测试集** | 统一按钮与文案 |

关系：
```
项目（题库大池子）
 ├─ 测试集 A（自带 问题+答案）
 ├─ 测试集 B（自带 问题+答案）
 └─ ...
```

数据实体不变：`TestSuite`（`suite_id`，归属某项目）装一组 `TestCase`（`id/question/question_type/expected_answer/key_points/expected_evidence/expected_entities/source/difficulty`）。答案 = `expected_answer` + `key_points`。

---

## 2. 黄金库「轻量退役」

- **去门禁**：检索层评分不再调用 `confirmed_gold_facts()` 的「确认才算数」逻辑，直接用测试集本题自己的 facts（`gold_facts(case)`）。
- **藏界面**：前端删除「黄金集库」卡片、「确认草稿」按钮，用户界面再无「黄金」字样。
- **后端留种**：gold 表、`save_gold/get_gold/list_gold/match_gold`、相关接口保留但不再被评分路径调用（便于日后恢复）。`generate_suite` 不再强依赖黄金确认。

> 通俗：取消「答案要先盖『已确认』章」的环节，导入的答案直接生效。

---

## 3. 删除项目

- 新增 `DELETE /api/v1/projects/{pid}`。
- **连带删除**该项目下全部数据：测试集（suites）、回答记录（responses/runs）、报告（run summaries）、检索结果。
- 前端项目列表每项加「删除」按钮，点击**二次确认弹窗**：「确定删除项目 X？其下所有测试集、评估结果将一并删除且无法恢复。」

---

## 4. 导入测试集命名

- 前端「导入测试集」流程：选文件 → **弹输入框填名称**（默认值＝文件名去扩展名）→ 提交。
- 后端 `POST /api/v1/projects/{pid}/suites:import` 接收 `name` 参数，存为该测试集的显示名（用于列表区分）。

---

## 5. 步骤流重做（4 步定稿）

**① 导入测试集 → ② 题库题目总览 → ③ 检索取证 → ④ 评分与报告**

- **①导入测试集**：导入/生成测试集进当前项目，导入弹框填名称。
- **②题库题目总览**：列出本项目下**所有测试集的所有题目**，可按测试集分组/区分；在此**逐题编辑**（问题/标准答案/要点/难度）与**增删整题**；编辑保存回对应测试集。测试集管理与编辑并入此步，不单列页面。
- **③检索取证**：检索层评估。
- **④评分与报告**：应用层评分 + L4 增量（uplift）报告。

UI 表现：
- 横向步骤条：序号圆圈 + 步骤标题；当前步高亮，已完成打勾，步骤间连接线；可点击跳转。
- 先实地起服务核对当前步骤区为何渲染成纯文字（CSS 未生效 / 缓存 / 渲染 bug），再据因修复，而非盲改样式。

## 6. 受影响文件（预估）

后端：
- `eval_api/app.py`：新增 `DELETE /projects/{pid}`；`suites:import` 加 `name` 参数；评分路径去黄金门禁。
- `eval_api/orchestrator.py`：`confirmed_gold_facts` 改为直接走 `gold_facts(case)`（或评分路径绕过门禁）；`generate_suite` 去黄金强依赖。
- `eval_api/sqlite_store.py`：新增项目级联删除所需方法（删 suites/runs/summaries）。

前端（`eval_web/static/`）：
- `app.js`：`FLOW_STEPS` 重定义 4 步；`renderFlowStepper` 重做；删黄金卡片与确认按钮；项目列表加删除按钮 + 确认弹窗；导入加命名弹框；第②步题目总览 + 逐题编辑/增删。
- `styles.css`：步骤条样式核对/修复；编辑表格、弹窗样式。
- `index.html`：如需新增容器。

测试：补 `DELETE projects` 级联、`suites:import` 命名、去门禁后检索评分用例。

## 7. 非目标（YAGNI）

- 不删除后端 gold 表/接口（仅退役）。
- 不做测试集版本管理、不做多用户权限。
- 不改 L0/L1/L3/L4 评分算法本身，仅改其取数来源（去黄金门禁）。
