# 评估工作台步骤重构 设计文档

- 日期：2026-06-15
- 范围：`runtime_eval/runtime_eval/eval_web`（静态 SPA，纯非模块化 JS，无构建）的「评估工作台」(`#/work`) 步骤结构
- 前置：本设计建立在同日已完成的「以项目为中心 IA 重构」（3 步工作台）之上，是对工作台内部步骤的**再分一刀**。

## 1. 背景与问题

刚完成的工作台是 3 步：`① 文档与出题 → ② 黄金校对 → ③ 评测与报告`。用户反馈步骤仍然"看不清"，三个具体痛点：

1. **一步塞太多**：步骤① 同时塞了 4 种造测试集的方式（上传+出题 / 导入 / 拉真实日志），步骤③ 又内含「取证据 / 打分与报告 / 报告历史」3 个子标签。
2. **不确定标准流程到底该是几步**：缺一个清晰的心智模型。
3. **步骤名字/文案看不懂**："取证据""黄金校对"等术语不自解释。

（用户明确表示步骤间"重叠/矛盾"不是主要痛点，但拆步后顺手收口重复入口。）

## 2. 心智模型：一次评估 = 一场考试（5 个动作）

设计的根基是与用户确认的"考试"类比：

| 考试类比 | 系统术语 | 谁来做 |
|---|---|---|
| ① 出考卷（题目） | 测试集 / 出题 | AI 出题，或从真实日志拉，或导入 |
| ② 写标准答案（答案 key） | 黄金答案 | AI 拟草稿 + 人校对确认 |
| ③ 收考生的答卷 | 取证据 | 被测系统实际检索/作答 |
| ④ 对答案打分 | 评分 | 大模型拿"答案 key"比对"考生答卷"打 0–3 分 |
| ⑤ 出成绩单 | 报告 | 系统聚合 HitRate/MRR/NDCG/召回 |

**Claude 在流程里出现 3 次，三种身份不可混淆：**
1. **出题老师**：出题 + 拟黄金草稿（→ ② 标准答案的来源之一）。
2. **考生**：③ 取证据时若无 serving 日志，让 Claude 挂工具去文档检索作答，其输出即"被测系统的答卷"（被打分对象）。
3. **打分老师**：④ 评分时拿黄金对照答卷打 0–3 分。

## 3. 新步骤结构（3 步 → 4 步）

把"打分+报告"从原步骤③ 中拆出，5 动作映射为 4 个可见步骤（打分与报告是连贯动作，合并为④；不拆成 5 步以免点击冗余）：

```
① 准备题目  →  ② 标准答案  →  ③ 取证据  →  ④ 评分与报告
```

### 3.1 步骤①：准备题目

- 顶部一个**三选一切换器**（互斥，平级不分主次）：`[AI 出题] [拉真实日志] [导入题库]`。选哪个就显示哪个的表单，不堆叠。
  - **AI 出题**：上传文档 → 选题型/数量 → 生成（自带黄金草稿）。*Claude 角色①*。
  - **拉真实日志**：domain / 检索器名 / limit → 从 serving 日志批量拉问题为草稿（命中黄金库自动回填）。
  - **导入题库**：上传 YAML/JSON 用例集。
- 下方**共用区**：本项目测试集列表 + 用例预览（不论题从哪来都汇到这里）。
- 出题/导入/拉取成功后选中该测试集，并把当前步骤推进到②。

### 3.2 步骤②：标准答案（黄金校对）

- 逐题复核 / 修正 / 保存黄金；黄金集库（按状态筛选 / 增删改 / 确认 / 批量确认本测试集草稿）。
- 醒目提示：**只有"已确认"的黄金才参与打分**。
- **删除**原步骤② 里的"批量评估（仅已标注）"按钮——它与步骤④ 的打分重复，拆步后统一收口到④。

### 3.3 步骤③：取证据（收被测系统的答卷）

- 两种取证方式并列：
  - **serving 批量取证**：检索器名 / domain → 从真实日志按问题取检索结果（SSE 实时进度）。
  - **Claude 自动作答**：Agent 名 / "仅补跑未完成" → 让 Claude 当考生挂工具检索作答。*Claude 角色②*。
- 逐题证据列表 + 取证进度。
- "去评分 →"按钮切到步骤④。

### 3.4 步骤④：评分与报告

- 打分前先展示**评估标准卡**（让用户知道按什么标准判）。
- **全部评分**（Claude 打 0–3 相关度，*Claude 角色③*）→ **生成最终报告** → 成绩单指标（HitRate/MRR/NDCG/召回）。
- 下方**报告历史**区块：列出本项目历次评测 run，可打开 HTML/MD 报告，空态有提示。

### 3.5 步骤条行为

- 沿用现有**软门禁** `flowReady`：未就绪的步骤灰显"待就绪"徽章但仍可点（不硬锁）。
- 就绪条件：② 需有题；③ 需有题且至少一条已确认黄金；④ 需有题、黄金且至少取到一条证据。
- 步骤名全用大白话，配一句话说明。

## 4. 路由与状态

- 路由不变：仍是单 token `#/work` + localStorage 记当前步与项目。
- `FLOW_STEPS` 从 3 项改 4 项：`docgen(准备题目) / gold(标准答案) / evidence(取证据) / report(评分与报告)`。
- 步骤索引：0=准备题目，1=标准答案，2=取证据，3=评分与报告。
- 默认步映射（按 `/api/v1/suites/{sid}/state` 的 `current_step`）：`documents/questions→0, gold→1, evidence→2, report→3`。
- 步骤①内的"三选一"切换器用一个 UI-local 变量（如 `state.docSource`，默认 `ai`）+ 可选 localStorage 记忆，不进路由。
- 步骤④内的报告历史是区块，不再是子标签，不需要 `evalTab` 状态——`kb_evaltab`/`evalTab` 及相关子标签逻辑（`workEvalTab`/`renderEvalTab`）删除。

## 5. 复用与改动清单

**直接复用（搬家）**：
- `suitesBody` 的上传/出题/导入/拉取片段 → 拆进步骤①三选一的三个分支（同一批按钮 id `uploadBtn`/`genBtn`/`importBtn`/`pullBtn` 仍由现有事件委托绑定）。
- 测试集列表/预览 `renderSuiteList`/`previewSuite` → 步骤①共用区。
- `goldBody` + 黄金集库（`renderGoldCases`/`loadGoldLib`/`confirmSuiteGold` 等）→ 步骤②。
- `flowStepEvidence` 主体 → 步骤③。
- `flowStepReport` 主体 + `renderReportListInto` → 步骤④。
- `flowReady`/`flowDone`/`flowRefresh`/`renderFlowStepper`/`/state` → 步骤条，仅把索引从 3 扩到 4。

**新写**：
- 步骤①的"三选一"切换器 + 按来源显示对应表单的分发。
- `workStepDocGen` 改为只渲染选中来源的表单 + 共用列表。
- 新增步骤③ 内容函数（取证据，从原 `workStepEval` 的 evidence 分支抽出）。
- 步骤④ 内容函数（评分 + 报告历史合一）。

**删除/改造**：
- 步骤③ 的子标签外壳（`workEvalTab`/`renderEvalTab`/`#evalTabBody`/`.tabs/.tab` 若不再用）。
- `state.evalTab` 与 `kb_evaltab` localStorage。
- 步骤② 的"批量评估（仅已标注）"按钮（与④打分重复）。
- `FLOW_STEPS` 3→4、`flowReady`/`flowDefaultStep`/`renderFlowStep` 分发改 4 步。
- 看板/列表里跳转的步骤索引（原"评测"= step 2 → 现"取证据"= step 2 / "评分"= step 3）需相应校准。

**后端**：不改任何 eval-api / eval-llm 端点；沿用现有 `/state`、suites、gold、reports、generate/preview、run-agent、serving 取证、eval-criteria 等接口。

## 6. 错误与边界处理

- 进入工作台无项目 → 复用 `noProjectBlock`。
- 未选测试集就切到 ②③④ → 复用 `pickHint` 空态提示。
- 步骤未就绪 → 软提示+灰显，不报错、不硬跳。
- 报告历史为空 → 空态卡片。
- 切换①内来源 → 只换表单区，测试集列表不重载丢失。

## 7. 测试策略

- 前端无构建、无既有前端单测框架；"测试"= ① 后端 pytest 回归保持全绿（重构不碰后端，基线 76 passed）② 浏览器手动核对。
- 同日新增的 `tests/test_eval_api.py::test_serves_eval_web_spa` 已断言新 IA；本次再调整后需同步其断言（如步骤数/文案/被删函数名）。
- 手动验收清单：
  1. 工作台显示 4 步：准备题目 / 标准答案 / 取证据 / 评分与报告。
  2. 步骤① 三选一切换器可切，三种来源表单各自正常；测试集列表共用不丢。
  3. 步骤② 校对/确认黄金正常；原"批量评估"按钮已无。
  4. 步骤③ serving 批量取证 + Claude 自动作答都在；逐题证据列表正常。
  5. 步骤④ 评估标准卡 → 全部评分 → 生成报告 → 成绩单；下方报告历史可开 HTML/MD。
  6. 步骤条软门禁正确（未就绪灰显但可点）。
  7. 刷新后按 localStorage 恢复到当前项目/步骤。
  8. 看板/测试集列表里的跳转落到正确的新步骤索引。

## 8. 非目标（YAGNI）

- 不做视觉风格大改（沿用现有 `styles.css`）。
- 不引入前端构建工具/框架。
- 不改后端数据模型与接口。
- 不把"打分"和"报告"拆成两个独立步骤（合并为④）。
- 不做多项目/多 run 并排对比等新功能。
